# Demo runbook

Everything here uses synthetic data. Nothing is sent to a government office, an email
address, or a paid API. There is no Toss integration.

## 1. Run it

```bash
npm ci                    # Node 22+ (node:sqlite); this environment uses Node 26
npm run db:reset -- --yes # optional: fresh synthetic database
npm run dev               # http://localhost:3000
```

Useful scripts:

| Command | What it does |
|---|---|
| `npm run check` | typecheck + lint + Vitest |
| `npm run e2e` | builds, then runs 14 Playwright tests against `next start` on port 3100 with a fresh `.local/e2e` |
| `npm run e2e:install` | installs Chromium once |
| `node scripts/capture.mjs <url>` | screenshots of home, create, draft and public pages |
| `node scripts/capture-community.mjs <url>` | moderator queue, public issue, feed |
| `node scripts/capture-followup.mjs <url>` | follow-up draft and approved states |

## 3. Fifteen-minute walkthrough

1. **Home** — read the scope card: real submission none, synthetic data, publication
   optional. Open “공개 제보 둘러보기”.
2. **Create** as 김민지 → choose a category, area, add a landmark and description, attach
   `public/samples/sidewalk.jpg` → “비공개 초안 만들기”.
3. **Owner draft** — the deterministic draft is editable. Point out the label
   “규칙 기반(모의)” and the verified channel card (안전신문고, checked 2026-11-19).
4. **Privacy review** — drag a rectangle over the photo, choose 가리기, click
   “서버 미리보기 만들기”. Explain that the preview is generated by the same server
   pipeline that publishes, and that masks are not saved until publication.
5. **Publish** — tick both acknowledgements, publish. The owner page becomes read-only
   and shows “공개됨”.
6. **Public issue** — open `/issues/<publicId>` in a private window (no cookies). Show
   the redacted photo, the narrow projection (no coordinates, no owner), and “공식 확인
   없음”.
7. **Support** — switch to 이하나, support the issue, click again: the count stays 1
   (“한 사람은 한 번만 집계됩니다”). Explain this is participation, not verification.
8. **Evidence** — upload a photo with the privacy confirmation. It is “검토 대기” and is
   invisible anonymously; the pending photo URL 404s.
9. **Moderation** — switch to 데모 운영자 → “검토” → approve the evidence with the photo
   visible. Reload the public page anonymously: the evidence now appears.
10. **Official status** — as moderator on the public issue, record an official status with
    `https://www.safetyreport.go.kr/`. Then as 김민지 record a citizen claim. Show that
    the public page lists “공식 확인 · 처리 중” and “시민 주장 · 미해결” separately, and
    the timeline keeps both labels.
11. **Follow-up** — as 김민지 open the owner page. With `CIVICPULSE_FOLLOWUP_WAITING_DAYS`
    set low (e.g. `0` for a demo) and approved evidence present, create the draft, read it,
    “검토 완료로 표시”, then use “안전신문고에서 직접 제출 ↗”. Say plainly: the app does
    not submit anything; the citizen does.

## 4. What not to claim while demoing

- No automatic face/plate detection. Manual masking is the product; the optional browser
  `FaceDetector` is experimental and was not available in the test environment.
- No AI model. Drafts and follow-ups are deterministic templates (`assistant_mode=mock`).
- No submission, no email, no SMS, no Toss SDK, no deployed production service.
- Support counts are demo accounts, not residents; official statuses only exist because a
  moderator typed them with a source.
- Evidence photos are moderated by a human; there is no automatic evidence redaction.

## 5. Failure checks worth showing

- Try publishing without ticking the acknowledgements → refused.
- Try publishing with zero masks and no “nothing sensitive” confirmation → refused.
- Sign out and open a draft URL → sign-in card; other user → 404.
- Open `/moderation` as a citizen → access denied.
- Try `POST /api/public/reports/<id>/support` with a foreign `Origin` → 403.
- Create a follow-up with no new approved evidence → refused with reasons.
